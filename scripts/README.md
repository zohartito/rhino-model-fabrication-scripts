# Script inventory

These 23 scripts are references from an undergraduate architecture studio. **The source model is not included, and every script needs adaptation.** There is no single entry point. Read [the failure record](../docs/what-worked-what-failed.md) before choosing an approach.

Runtime labels below are based on the imports and syntax, not successful execution. **Rhino / CPython 3** means the Rhino 8 script editor with CPython 3 and RhinoCommon. `scriptcontext` supplies the active document where used; `rhinoscriptsyntax` and `System.Drawing` are Rhino/.NET dependencies. **Headless / CPython 3** means a standalone Python interpreter with the listed libraries. The prototype, CLT repacker, and West splitter use postponed type annotations; the two STL repackers use f-strings. No script has Python 2-only print statements or was classified as IronPython 2.7-only. IronPython compatibility was not tested.

At initial publication, every script passed `python3 -m py_compile` under CPython 3.15.2; none was run or imported. Subsequent [audit regressions](../docs/audit-regressions.md) exercise bounded headless cases. Compilation does not check Rhino API overloads, dependency versions, file availability, model selection, or fabrication output. Library versions are not pinned.

## Path settings

Each table lists existing constants whose personal paths were replaced, or new constants for former home-folder fallbacks. All placeholders begin with `path/to/`. Set them to your own paths before adapting the script. Create parent directories yourself where the code does not create them.

For active-document exporters, `DEFAULT_MODEL_PATH` is used only when `sc.doc.Path` is empty. A saved document still determines its own output directory. `SUMMARY_DIR` separately controls the two panel exporters' summary logs. For the CLT repacker, point `SOURCE_SCRIPT` to the included `prototype_exact_clt_laser.py`; it dynamically imports that file. `PROJECT_ROOT` supplies the default output folder, and `--source` can override the prototype's source model.

## rhino-bambu — 9 scripts

These attempt to turn return surfaces or facade solids into meshes and plate layouts. They write STL/3DM files and logs; they do not control a printer or call Bambu Studio.

Common print packing parameters, where present, are `250 × 250 mm`, with `5 mm` margins and spacing. The original `rhino_make_printable_returns.py` instead makes one unbounded row with a `10 mm` margin. Placement at Z=0 does not establish the correct print orientation. Exported files and layers with `PRINT_READY` or `FINAL` in the name still need inspection.

## clt-laser — 4 scripts

All four use `rhino3dm` and Shapely (including the prototype imported by the repacker). They work with layer `20_CLT_THICK_REMAP_49FT_BACKUP_WALL_V68`. The first three write SVG sheets and a Rhino drawing; the repacker writes a packed Rhino drawing, JSON manifest, and Markdown guide.

The generators assume **real feet in the source** and multiply by `0.5` for output inches; the recorded unit setting is not a validation or automatic conversion. Stock is `12 × 12 in`, margin `0.125 in`, usable span `11.75 in`, vertical scoring interval `2.5 in` (five source feet), bed guide `32 × 18 in`. The notes describe `1/8 in` plywood, but these scripts generate 2D geometry and do not model stock thickness or kerf. Colors distinguish cut/score/guides/labels, not machine power or speed settings.

## trials — 5 scripts

This folder keeps approaches that did not work, along with the diagnostics and correction that explain the change. In particular, broad-face-down returns produced excessive support and poor packing in the original notes. The compact four-plate trial preserved that orientation; it did not fix it. The upright two-plate repacker records the subsequent correction, so its presence here does not mean the notes call it a failed orientation. Neither the diagnostics nor the repackers are general tools, and none was rerun for this copy.

## Limits retained in the code

Changes beyond the initial path settings and prototype header scrub are limited to the documented [audit fixes](../docs/audit-regressions.md). Generated notes may still use words such as "verified" or "corrected" from the original session. Those strings are part of the record and do not establish validation on another model.

The notes' 13-subobject example does not override the `19` in `preserve13`. Likewise, the notes' upright return orientation does not override the flat-face mapping still enabled in the West batch exporter. Inspect the code and the resulting geometry after adapting it; do not choose a script by filename alone.
